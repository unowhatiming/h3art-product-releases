# 摇滚人格测试 · 设计说明

> 一句话：用 24 道题把你在四组对立上的倾向测出来，映射到 16 种摇滚人格之一，
> 每种人格对应一位中国摇滚乐手作为「性格演绎」。结构参考 MBTI / SBTI，题目与文案为原创。

| 项目 | 说明 |
| --- | --- |
| 题量 | 24 题（每个维度 6 题） |
| 题型 | 二选一强迫选择（A / B），避免中立答案稀释人格 |
| 题序 | **每局随机打乱**，重测时顺序不同；计分前还原回原题号，结果不受顺序影响 |
| 计时 | 全程计时，结果页显示总用时与平均每题耗时 |
| 维度 | 4 组对立，共 16 种组合 |
| 时长 | 约 4–6 分钟 |
| 交付 | 单文件 `rock-personality.html`，零依赖，双击即用 |

## 一、四维模型

沿用 MBTI 的四字母代号，但每一维都重新定义为「一个人身上真实存在的分歧」，而不是音乐技能。
题库只问你这个人在生活里怎么活（怎么跟人打交道、怎么处理冲突、怎么过日子），不问排练、录音、上台这类工作场景。

| 代号 | 维度 | 左极 | 右极 | 这一维在问什么 |
| --- | --- | --- | --- | --- |
| EI | 能量方向 | **外放**（E） | **内收**（I） | 你在哪儿充电，就在哪儿放电 |
| SN | 感知方式 | **现实**（S） | **想象**（N） | 你怎么接收这个世界 |
| TF | 处理方式 | **硬处理**（T） | **软处理**（F） | 情绪来了，你拿它怎么办 |
| JP | 生活秩序 | **编排**（J） | **即兴**（P） | 你怎么把日子过成节奏 |

为什么是这四维：它们对应一个人身上四个真实的问题——
**你怎么跟人相处（能量）· 你怎么看世界（感知）· 你怎么处理冲突（情绪）· 你怎么过日子（秩序）。**
四者组合出的 16 型，恰好能覆盖从崔健到窦唯、从何勇到梁龙的整条性格光谱。

## 三、题目（24 题，逐题标注）

选项顺序刻意打散：**A 位并不总是同一极**，避免“一直选 A”就得到极端结果。

每道题都是生活场景，不是音乐工作场景——`rock-test-verify.mjs` 里有一道断言：题面出现“排练/录音/上台/乐队”等词即失败。

### 能量方向（外放 E ↔ 内收 I）

**EI-1**（原始题号 1）一屋子你都不认识的人。

- A｜二十分钟，我全混熟了　→ **外放**
- B｜我找了最靠里的位置坐下　→ **内收**

**EI-2**（原始题号 5）手机响了，陌生号码。

- A｜让它响完，回头发消息问是谁　→ **内收**
- B｜直接接　→ **外放**

**EI-3**（原始题号 9）一个周末，没人约你。

- A｜你会主动找人，闲着难受　→ **外放**
- B｜你松了口气，终于没人找你　→ **内收**

**EI-4**（原始题号 13）刚确定一件好事。

- A｜自己先消化几天　→ **内收**
- B｜立刻告诉所有人　→ **外放**

**EI-5**（原始题号 17）聚餐散场了。

- A｜还不想走，谁再续一场　→ **外放**
- B｜心里已经在算打车时间　→ **内收**

**EI-6**（原始题号 21）排队排了四十分钟，队伍不动了。

- A｜继续站着，心里默算还要多久　→ **内收**
- B｜去问工作人员到底怎么回事　→ **外放**

### 感知方式（现实 S ↔ 想象 N）

**SN-1**（原始题号 2）看完一部电影，你最先记住的是——

- A｜具体的人、具体的场景　→ **现实**
- B｜它到底想说什么　→ **想象**

**SN-2**（原始题号 6）别人跟你讲一件事，你更容易记住——

- A｜整件事到底对不对、有多不对　→ **想象**
- B｜细节：几点、谁说了什么　→ **现实**

**SN-3**（原始题号 10）你更烦哪一种人——

- A｜满嘴概念，却说不清一件具体的事　→ **现实**
- B｜只看表面，从不问为什么　→ **想象**

**SN-4**（原始题号 14）做决定时你更信——

- A｜一种说不清、但很准的预感　→ **想象**
- B｜具体的证据和先例　→ **现实**

**SN-5**（原始题号 18）你更愿意聊——

- A｜最近干了什么、吃了什么、见了谁　→ **现实**
- B｜为什么会这样、以后会变成什么样　→ **想象**

**SN-6**（原始题号 22）无聊的时候你在干嘛？

- A｜发呆。脑子里在放另一部电影。　→ **想象**
- B｜找点具体的事做：收拾、跑腿、看比赛　→ **现实**

### 处理方式（硬处理 T ↔ 软处理 F）

**TF-1**（原始题号 3）朋友做了一件明显不靠谱的事。

- A｜我直接告诉他哪一步不对　→ **硬处理**
- B｜我先陪他难受，再慢慢说　→ **软处理**

**TF-2**（原始题号 7）你更受不了别人这样说你——

- A｜「你太情绪化，不专业。」　→ **软处理**
- B｜「你太会算计，不真诚。」　→ **硬处理**

**TF-3**（原始题号 11）一件重要的事被你搞砸了。

- A｜先找原因：哪一步错了　→ **硬处理**
- B｜先难受：觉得对不起大家　→ **软处理**

**TF-4**（原始题号 15）有人找你借一笔不小的钱。

- A｜心里为难，但不好意思拒绝　→ **软处理**
- B｜先问用途，把还款时间说清楚　→ **硬处理**

**TF-5**（原始题号 19）吵架之后——

- A｜非把事情说明白，谁对谁错　→ **硬处理**
- B｜只想关系先和好，对错不重要　→ **软处理**

**TF-6**（原始题号 23）你做的决定通常是——

- A｜心里舒服就定了　→ **软处理**
- B｜把利弊想清楚再定　→ **硬处理**

### 生活秩序（编排 J ↔ 即兴 P）

**JP-1**（原始题号 4）出门旅行。

- A｜行程表、餐厅，都提前订好　→ **编排**
- B｜到了再说　→ **即兴**

**JP-2**（原始题号 8）你的房间。

- A｜东西都在「随手能拿到」的位置　→ **即兴**
- B｜东西都有固定位置　→ **编排**

**JP-3**（原始题号 12）明天要早起。

- A｜今晚就把衣服和包收拾好　→ **编排**
- B｜明早起来再翻　→ **即兴**

**JP-4**（原始题号 16）一份要交的活。

- A｜最后一晚才真正进入状态　→ **即兴**
- B｜提前几天做完，最后一天只检查　→ **编排**

**JP-5**（原始题号 20）计划突然被改了。

- A｜我会烦躁，得重新排一遍　→ **编排**
- B｜无所谓，反正也没几次完全按计划走过　→ **即兴**

**JP-6**（原始题号 24）你的手机待办和相册。

- A｜一堆过期的事，照片随手存　→ **即兴**
- B｜分类、清单、该删的早删了　→ **编排**

## 四、计分规则

1. 每个维度统计两极被选中的次数，多数方决定该维度的字母。
2. 四个字母按 `能量 + 取材 + 处理 + 秩序` 顺序拼成代号（如 `ENFP`），**16 种组合各对应一种人格**。
3. 每维 6 题，可能出现 3:3 平局。平局时**以该维度最后一题的选择为准**，并在结果页明确写出「平局」，不隐藏。
4. 条形百分比 = 该极得票 / 该维总票数，用于展示倾向强度，不参与判定。
5. 题序随机：作答按「出场位置」记录，结算前用 `mapAnswers(order, answers)` 还原成「原始题号」再计分，因此同一份作答无论顺序怎么换，结果都一样（有测试保证）。
6. 16 型全部可达（已用 20 万次随机题序 + 随机作答验证覆盖率为 16/16）。

## 五、结果页包含什么

- 人格代号（大字）+ 人格名 + 代表乐手与作品 + 稀有度
- 一句话定性（tagline）+ 三个特征标签 + **用时与平均每题耗时**
- 四维度条形图（含平局提示）
- 四张卡片：**你的杀招 / 你的死穴 / 你的人群位置 / 你怎么爱**
- **适合你的三首歌**（每个类型一份歌单）
- 属于这个类型的一句话（附出处）
- **最佳搭档 / 最易炸** 两个互补或相冲的类型
- **你的摇滚名片**：内联 SVG 四维雷达（每条轴取该维胜出那一极的百分比，越靠外越极端）
- **分享海报**：Canvas 现画，三档尺寸可切换 —— 竖版 1080 × 1440 / 方图 1080 × 1080 / 横版 1200 × 900，可长按保存或一键下载
- 一键复制分享文案、再测一次

## 六、交互与实现

| 项 | 实现 |
| --- | --- |
| 依赖 | 无。单个 HTML 文件，内联 CSS/JS，无外链、无字体请求 |
| 键盘 | `1`/`A` 选 A，`2`/`B` 选 B，`←` 返回上一题 |
| 状态 | 记住已选答案，可随时回退修改；答完自动结算 |
| 题序 | Fisher–Yates 洗牌，可注入 rng 以便测试复现 |
| 计时 | 右上角实时时钟（500ms 刷新），结算时停表 |
| 海报 | Canvas 2D 绘制，三档版式各有一套排版参数（`posterLayout`）；`toDataURL` 输出 PNG，按需生成并缓存；无 Canvas 支持时该区块自动隐藏 |
| 名片 | 雷达图用内联 SVG 现算坐标，不依赖 Canvas，任何环境都能显示 |
| 视觉 | 黑底 + 红色强调 + 扫描线噪点 + 分段入场动画，`prefers-reduced-motion` 下自动降级 |
| 分享 | `navigator.clipboard`，失败时回退到 `execCommand` |
| 响应式 | 单列（手机）→ 双列卡片（≥700px） |

## 七、如何改

打开 `rock-personality.html`，脚本里有三个纯数据块，改完即生效：

- `DIMS`：四维的代号、名称、两极标签。改这里会连带影响结果页条形图与海报。
- `QUESTIONS`：题目数组。每题 `{ dim, q, a:{pole,t}, b:{pole,t} }`，`pole` 必须是该维的两个字母之一。
- `TYPES`：以四字母代号为 key 的人格数据（含 `songs` 三首歌单、`best`/`clash` 配对）。**必须覆盖全部 16 个组合**，否则会出现无结果的情况。

注意：`tagline` 会同时出现在结果页和海报上，建议控制在 30 字以内（测试里有一条长度断言）；`songs` 需为 3 条且包含代表作 `song`（同样有断言）。

海报改版式：改 `POSTER_SIZES` 增减尺寸，再改 `posterLayout()` 里对应那一档的坐标即可（坐标系是绝对像素）。

改完可以跑一遍自检（node 环境）：

```bash
node .build/rock-test-verify.mjs   # 数据完整性 / 题序随机 / 16 型可达 / 计分性质 / 计时格式
node .build/rock-dom-smoke.mjs     # 全流程渲染冒烟测试（无 Canvas）
node .build/rock-poster-test.mjs   # 海报绘制测试（假 Canvas 记录每次绘制调用）
node .build/gen-doc.mjs            # 重新生成本文档
```

## 八、自检：怎么确认它是真的能跑

改完题目/文案后，`.build/` 里这几条可以直接跑（纯 node，无需装依赖）：

| 脚本 | 覆盖内容 |
| --- | --- |
| `rock-test-verify.mjs` | 结构与文案完整性、选项左右平衡、题序随机是合法排列且可复现、`mapAnswers` 逆映射、**计分与题序无关**、16 型可达（20 万次随机）、平局回退、计时格式 |
| `rock-dom-smoke.mjs` | 自带最小 DOM 垫片，跑完「开始 → 24 题 → 回退 → 结算 → 复制 → 重测 → 键盘」全流程，并交叉核对页面结果与核心计分 |
| `rock-poster-test.mjs` | 用记录型假 Canvas 检查三档海报：各档画布尺寸、代号四字母、类型名、乐手、四条进度条矩形是否填满、金句、几何不越界、切档缓存复用、下载锚点 |
| `visual-check.mjs` | 解码无头浏览器截图做像素级断言：暗色主题、各分区文字是否画出、进度条红/灰分段、内容不压边、页面未被截断 |
| `gen-doc.mjs` | 从页面数据反向生成本文档，保证文档不跑偏 |

真实浏览器截图存放在 `.build/shots/`（`1-intro` / `2-quiz` / `3-result` / `4-result-wide` / `poster`），可直接打开核对视觉。
